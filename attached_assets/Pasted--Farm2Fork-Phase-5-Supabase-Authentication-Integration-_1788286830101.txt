2. SUPABASE AUTHENTICATION
==================================================

Use Supabase Auth for:

- email/password registration
- email/password login
- logout
- session management

Use the Supabase project configuration already available to the application.

Do NOT put SUPABASE_DATABASE_URL in the frontend.

The frontend must NEVER receive the PostgreSQL connection string.

Only public Supabase client configuration may be used in the frontend.

Never expose:

- database password
- service-role key
- SUPABASE_DATABASE_URL

==================================================
3. BACKEND JWT VERIFICATION
==================================================

FastAPI must verify authenticated requests.

Implement a reusable authentication dependency.

Conceptually:

Authorization:
Bearer <SUPABASE_ACCESS_TOKEN>

FastAPI should:

1. Extract the Bearer token.
2. Validate the Supabase JWT securely.
3. Obtain the authenticated user's UUID.
4. Use that UUID for authorization and database operations.

Do NOT trust:

- farmer_id supplied by frontend
- buyer_id supplied by frontend
- profile_id supplied by frontend
- arbitrary user_id supplied by frontend

Ownership must come from the authenticated user's identity.

==================================================
4. AUTH ENDPOINTS
==================================================

Create only the minimum required backend authentication/identity endpoints.

Recommended:

GET /api/auth/me

Response should provide safe authenticated user information such as:

{
  "id": "...",
  "email": "...",
  "role": "FARMER"
}

Do not return:

- password
- database credentials
- service-role credentials
- sensitive Auth internals

If login/register is handled directly by Supabase Auth on the frontend, do NOT unnecessarily duplicate password authentication in FastAPI.

==================================================
5. PROFILE CREATION
==================================================

After successful Supabase Auth registration:

Create the corresponding public.profiles record.

Required:

profiles.id = auth.users.id

Store:

name
role
mobile
location

Then create either:

farmers.profile_id = profiles.id

OR:

buyers.profile_id = profiles.id

depending on the selected role.

Do NOT allow a user to create both farmer and buyer records through the normal registration flow unless the existing product requirements explicitly support that.

7. LOGIN FLOW
==================================================

Login should:

1. Authenticate through Supabase Auth.
2. Obtain access token/session.
3. Store session securely using the Supabase client/session mechanism.
4. Send access token with protected FastAPI requests.
5. FastAPI verifies the token.
6. FastAPI identifies the user.
7. Retrieve profile/role.
8. Return the appropriate application state.

Role-based navigation:

FARMER → Farmer Dashboard

BUYER → Buyer Marketplace

ADMIN → Admin Dashboard

Do not trust frontend-only role checks for authorization.

Backend authorization must remain authoritative.
